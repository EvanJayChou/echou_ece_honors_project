robot_slam
=========

This package provides two stage-specific launches for mapping and localization using Nav2 and SLAM Toolbox.

**Prerequisites**

- ROS 2 (Humble or Jazzy). Ensure `$ROS_DISTRO` is set to your ROS 2 distribution.
- Typical Nav2 and SLAM Toolbox packages installed (these are listed in package.xml).

**Quick workspace bootstrap**

A helper script lives at the workspace root: [source_ros2.sh](../..//source_ros2.sh)

When you source it from the workspace root, it now automatically:

1. Sources `/opt/ros/${ROS_DISTRO}/setup.bash`
2. Runs `colcon build --symlink-install`
3. Sources `install/setup.bash`

Example:

```bash
source ./source_ros2.sh
```

**Launch files**

- Stage 1 (Mapping): [launch/launch_stage_1.launch.py](launch/launch_stage_1.launch.py)

  Starts the mapping stack, plus the mission bridge nodes that record the route and capture mission artifacts. RViz is optional so the launch can run headless by default. Run:

  ```bash
  ros2 launch robot_slam launch_stage_1.launch.py
  ```

  To open RViz from the launch, pass:

  ```bash
  ros2 launch robot_slam launch_stage_1.launch.py use_rviz:=true
  ```

  Optional overrides:

  ```bash
  ros2 launch robot_slam launch_stage_1.launch.py use_rviz:=true
  ```

- Stage 2 (Localization & Navigation): [launch/launch_stage_2.launch.py](launch/launch_stage_2.launch.py)

  Starts localization against the saved map, the Nav2 navigation stack, and the mission bridge nodes used to finalize Stage 3 data capture. Run (example):

  ```bash
  ros2 launch robot_slam launch_stage_2.launch.py map_yaml:=/absolute/path/to/your_map.yaml
  ```

  If you don't supply `map_yaml` it defaults to a sample map provided by `ucsd_robocar_nav2_pkg` (declared as a dependency).

**RViz layouts**

- Mapping layout: `rviz/mapping.rviz`
- Localization layout: `rviz/localization.rviz`

**Notes and tips**

- The Stage 2 launch expects a saved map (YAML + PGM). Point `map_yaml` to the YAML file generated by `slam_toolbox` or another mapper.
- Stage 1 and Stage 2 both include the mission bridge nodes so route and image data are available for the rest of the workflow.
- SLAM Toolbox config namespace was adjusted to be compatible with the standard launch files (see `config/slam_toolbox.yaml`).
